# 第3章 Project Philosophy

---

# 3.1 Philosophy（基本理念）

BaseKitは、一つの業務システムを完成させることを目的としたプロジェクトではない。

本プロジェクトの目的は、様々なシステムで共通して利用できる基盤を構築し、その上で自由に機能を追加・拡張できる環境を提供することである。

BaseKitは「完成品」ではなく、「土台」である。

そのため、Coreには共通機能のみを実装し、業務固有のロジックはすべてPluginとして独立させる。

---

# 3.2 Minimal Core

Coreは必要最小限に保つ。

Coreへ新しい機能を追加する基準は、「複数の実証プロジェクトで共通して必要と判断されたもの」に限定する。

Coreを肥大化させないことは、BaseKitの最も重要な設計原則の一つである。

Coreは機能数を競うものではなく、安定性と再利用性を提供するための基盤である。

---

# 3.3 Plugin First

BaseKitでは、業務機能はCoreではなくPluginとして実装する。

例えば、

* CRM
* SNS
* 会計
* 在庫管理
* 株価分析
* ロト予想
* その他業務システム

これらはすべて独立したPluginとして設計する。

Plugin同士は必要最小限の依存関係に留め、Coreとのインターフェースを通じて連携する。

これにより、特定の業務ロジックがBaseKit全体へ影響を与えることを防ぐ。

---

# 3.4 Specification First

BaseKitでは、コードより仕様書を優先する。

仕様書は単なる設計資料ではなく、プロジェクト全体の共通言語である。

すべての実装は仕様書を基準として行い、仕様変更が必要な場合は、まず仕様書を更新し、その後に実装を行う。

これにより、

* AIによる実装
* AIによるレビュー
* 人による保守

のすべてを同じ基準で進めることができる。

---

# 3.5 AI Native Development

BaseKitは、AIとの共同開発を前提として設計されている。

AIは単なるコード生成ツールではなく、

* 設計支援
* 実装支援
* レビュー
* テスト
* ドキュメント整備

を担う開発パートナーとして位置付ける。

また、AIが誤って不要な変更を加えないよう、Unit単位で独立した構造を採用する。

---

# 3.6 Unit Architecture

BaseKitでは、可能な限り機能を小さな単位（Unit）へ分割する。

Unit化の目的は、

* 再利用性の向上
* AIによる変更範囲の限定
* 保守性の向上
* テスト容易性の向上

である。

一つのUnitは、一つの責務のみを持つ。

複数の責務を持つUnitは設計を見直す対象とする。

---

# 3.7 Verification Before Standardization

BaseKitでは、最初から共通化を行わない。

まず実際のシステムを開発し、複数のプロジェクトで共通して利用された機能のみをBaseKitへ取り込む。

この方針により、机上の設計ではなく、実績に基づくCoreを構築する。

共通化は設計者の予測ではなく、実証結果によって判断する。

---

# 3.8 AI Collaboration

AIには、それぞれ異なる役割がある。

BaseKitでは、AIを役割ごとに活用することを推奨する。

例として、

・アイデア整理

・仕様書作成

・実装

・レビュー

・テスト

などを役割分担し、それぞれ得意分野を活かして開発を進める。

重要なのは、一つのAIにすべてを任せることではなく、仕様書を共通基盤として複数のAIを活用することである。

---

# 3.9 OSS Philosophy

BaseKitは、一人の開発者がすべての機能を提供することを前提としない。

本プロジェクトでは、Coreのみを公式に提供する。

Pluginについては、公式Pluginだけでなく、利用者やコミュニティによる自由な開発を歓迎する。

BaseKitは、利用者が自由に拡張できる土台であり、成長し続けるOSSを目指す。

---

# 3.10 Design Principles

BaseKitでは、以下を設計原則とする。

* Coreは最小限に保つ。
* 業務ロジックはPluginへ実装する。
* 実証された機能のみ共通化する。
* 仕様書を最優先とする。
* Unit単位で設計する。
* AIとの協調開発を前提とする。
* OSSとして拡張可能な構造を維持する。
* 後方互換性を可能な限り維持する。

---

# 第3章まとめ

BaseKitの目的は、多機能なフレームワークを作ることではない。

必要最小限のCoreを提供し、実証された共通機能だけを資産化することで、長期的に成長できる開発基盤を構築することである。

仕様書を中心としたAIとの共同開発、Pluginによる拡張、Unit単位の設計、そしてOSSとしての自由な発展。

これらの理念が、BaseKitのProject Philosophyを構成する。
